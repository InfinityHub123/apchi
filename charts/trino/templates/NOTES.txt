This chart creates none of the Secrets Apchi writes configuration into -- they are Apchi's
data and Apchi's chart creates them. So if the coordinator is not starting, check they exist:

  kubectl -n {{ .Release.Namespace }} get secret {{ .Values.secrets.accessControl }} {{ .Values.secrets.certificateMapping }}

Trino reads both of those while loading and refuses to boot when either is missing. Install
Apchi first:

  helm install apchi oci://ghcr.io/infinityhub123/charts/apchi \
    --namespace {{ .Release.Namespace }} \
    --set trino.host={{ include "trino.fullname" . }} \
    --set trino.coordinatorDeployment={{ include "trino.coordinatorName" . }} \
    --set trino.workerDeployment={{ include "trino.workerName" . }} \
    --set mongodb.uri=mongodb://your-mongo:27017

Apchi refuses to Apply against a deployment it cannot configure correctly and names what is
wrong, so a mismatch above surfaces as a precondition failure rather than as a lost change.

One coordinator, by design rather than by omission: Trino cannot drain a coordinator, so a
configuration change that needs a restart destroys every running query. See ADR-0003.
